# 로컬 변경 리뷰

구체적인 결함, 경계 위반과 검증 공백을 우선한다.

1. 루트·대상 경로의 `AGENTS.md`를 읽고 git diff로 변경 범위를 확인한다. 첫 커밋 전이면 비교할 원본과 파일 목록을 확보하고 diff가 없다는 이유로 변경이 없다고 판단하지 않는다.
2. 변경과 관련된 `docs/ARCHITECTURE.md`, `docs/ADR.md` 부분만 읽는다. 루트 불변식·README 협업 규칙을 반복 정의하지 않는다.
3. 새 동작의 단위·경계 테스트, 모듈 의존 방향, 비밀·민감정보 노출, 관련 빌드·검증 결과를 확인한다.
4. 심각도 순으로 findings를 제시한다. 파일·줄, 발생 조건, 영향과 가장 작은 수정안을 포함한다.
5. 문제가 없으면 명확히 말한다. 실행하지 않은 검사는 `Not-tested`로 남긴다. 코드를 읽은 결과와 실제 실행 결과를 구분한다.

표를 요청받으면 `항목 | PASS/FAIL | 근거·수정안` 형식을 사용한다. 추측만으로 결함을 만들지 않는다.
