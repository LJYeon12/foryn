이 문서는 채팅의 저장 결과 확인 지연, 미완료 작업 증가 또는 `CHAT5031`이 발생했을 때 본다.

# 채팅 저장과 복구

## 실행 범위

현재 저장소는 운영 연결을 제거한 개발 복사본이다. 이 문서는 구현된 로컬 복구 동작과 운영 재개 조건을 설명한다. 실제 GCP 프로젝트·리전·Cloud Run 서비스는 연결되어 있지 않다. 현재 문서의 명령으로 운영 배포·트래픽 전환을 수행하지 않는다.

메시지와 세션은 MongoDB에 저장한다. MySQL의 `chat_operations`는 처리 기록이고 `chat_operation_guards`는 사용자별 작업권이다. MongoDB의 `chat_write_guards`는 지연된 실행자의 쓰기를 막는 문서다. 이 세 곳에 대화 원문이나 건강 프로필 사본을 넣지 않는다.

## 먼저 확인할 내용

DB의 읽기 전용 연결에서 다음 정보를 확인한다. 작업 ID는 장애 대상에서 확인한 실제 값으로 바꾼다. 프로필·메시지 원문을 로그로 출력하지 않는다.

```sql
SELECT status, COUNT(*) AS operations
FROM chat_operations
GROUP BY status;

SELECT operation_id, user_id, kind, status, sql_committed,
       attempts, lease_until, next_attempt_at, created_at, updated_at, last_error
FROM chat_operations
WHERE status NOT IN ('COMPLETED', 'CANCELLED')
ORDER BY created_at
LIMIT 20;
```

시각 열은 UTC epoch milliseconds다. 같은 작업의 MySQL 기록, MongoDB 작업권, 세션의 임시 상태와 메시지 개수를 대조한다. DB가 연결되지 않았거나 기존 SQL 쓰기가 진행 중이면, `sql_committed`가 보이지 않는 것만으로 롤백을 단정하지 않는다. 실제 복구 코드는 primary의 별도 트랜잭션에서 작업권과 처리 기록을 잠금 읽기한다.

## 상태와 조치

| 상태 | 의미 | 처리 |
| --- | --- | --- |
| PREPARING | 응답 준비 또는 저장 진행 중 | 기본 300초 작업권이 만료되기 전에는 다른 쓰기를 차단한다. |
| RECOVERING | 복구자가 새 작업권을 확보함 | 같은 작업의 결과 확인·확정·보상을 수행한다. |
| RETRY | 이번 복구 시도 실패 | 다음 실행 시각에 다시 처리한다. 작업권은 계속 점유한다. |
| MANUAL | 복구 실패가 8회 누적됨 | 원인을 점검한다. 작업권을 삭제해 새 쓰기를 허용하지 않는다. |
| COMPLETED | 대화 확정 완료 | 작업권을 해제한다. |
| CANCELLED | 미반영 또는 임시 자료 정리 완료 | 작업권을 해제한다. |

복구는 애플리케이션 준비 완료 시점과 실행 중 기본 10초 간격으로 최대 20건씩 조회한다. 재시도 대기는 2·4·8·16·32·60·60초이며, 실패가 8회 누적되면 MANUAL로 남긴다. 프로세스가 종료되면 진행 중 기록은 남으며, 새 실행자는 작업권 만료 뒤 이어서 처리한다. `chat.recovery.enabled=false`는 검색을 끈다. 작업권과 미확정 자료를 삭제하는 설정이 아니다.

현재 종료 작업의 자동 삭제는 없다. 원문 없는 메타데이터라도 저장량을 측정하고 보관 기간을 확정해야 한다. 보관 정리는 미완료 기록을 제외하고 별도 검증해야 한다. 두 저장소의 사용자별 작업권 문서는 이전 실행자의 쓰기를 차단하므로 처리 기록과 함께 임의 삭제하지 않는다.

## 확정과 보상 규칙

~~~mermaid
flowchart TD
    Inspect[SQL 잠금 읽기와 Mongo 작업권 갱신] --> Done{Mongo 확정 완료?}
    Done -->|예| Finish[완료 기록과 작업권 해제]
    Done -->|아니오| SQL{프로필 커밋 표시 확인?}
    SQL -->|예| Publish[기존 임시 자료 확정 재시도]
    Publish --> Finish
    SQL -->|롤백 확인| Cancel[해당 작업의 임시 메시지·상태 정리]
    Cancel --> Release[취소 기록과 작업권 해제]
    SQL -->|확인 불가| Retry[재시도 또는 점검 상태 유지]
~~~

프로필 커밋 표시가 확인되면 프로필을 과거 값으로 되돌리지 않는다. 같은 작업의 저장된 응답으로 MongoDB 확정을 완료한다. 롤백이 확인된 경우에는 해당 작업의 PENDING 메시지와 임시 세션 상태만 정리한다. 확정된 대화 전체를 과거 스냅샷으로 덮어쓰지 않는다.

복구자는 먼저 SQL 작업권의 fence를 증가시키고, MongoDB에서도 같은 사용자 작업권 문서를 조건부로 갱신한다. 기존 작업이 뒤늦게 돌아오면 쓰기가 거절되거나 트랜잭션 충돌로 취소된다. 세션 삭제도 같은 문서를 변경하므로 지연된 작업이 세션을 되살릴 수 없다.

회원 초기화·삭제에서는 상위 MySQL 트랜잭션이 끝날 때까지 사용자 작업권 잠금을 유지한다. 이 처리가 회원 관련 모든 DB 변경의 전역 원자성을 보장하지는 않는다.

User UPDATE는 실제 변경 열만 기록한다. 닉네임 수정의 오래된 엔티티가 채팅 프로필을 되돌리지 않게 하는 규칙이다. 회원 초기화는 작업권 확보 뒤 최신 User를 잠금 refresh한 다음 수행한다.

## 사용자 응답과 알림

- `CHAT4091`: 이전 작업이 진행 중이다. 같은 응답을 즉시 다시 전송하지 않는다.
- `CHAT4092`: 처리 중 대상 상태가 변경되었다. 현재 대화를 다시 조회한다.
- `CHAT5031`: 저장 결과 확인 또는 복구가 필요하다. 기존 `GET /api/v1/chat/history/past-24h`로 확정 이력을 확인한다.
- `CHAT5001`: 저장이 확정되지 않았으며 정리가 완료된 경우에 반환할 수 있다.

`GET /api/v1/chat/session`도 새 세션을 생성할 수 있어 작업권을 획득한다. 작업 중에는 충돌 응답이 날 수 있다. 진행 상태의 단순 조회에는 이력 조회를 사용한다.

알림 예약·취소는 대화 확정과 완료 기록 뒤에 실행한다. 알림 오류는 확정된 대화를 취소하지 않는다. 기존 알림은 메모리 예약이며, 재시작 후 예약 복원이나 정확히 한 번 전달은 이 구현의 보장에 포함하지 않는다. 백그라운드 복구에서 알림 부수 효과를 재생하지 않는다.

## 관측

| 지표 | 의미 |
| --- | --- |
| chat_recovery_pending | 최근 검색에서 확인한 미완료 작업 수 |
| chat_recovery_oldest_age_ms | 확인된 가장 오래된 미완료 작업의 체류 시간 |

| chat_recovery_results_total | 완료·취소·보류 결과별 횟수 |

사용자 ID·작업 ID는 메트릭 label로 넣지 않는다. 원문과 프로필은 오류 로그에 넣지 않는다. DB 검색 자체가 실패하면 마지막 지표값이 유지되므로 검색 실패 로그와 수집 시각도 함께 확인한다.

## 전환과 되돌리기

V14는 MySQL 작업 기록·작업권을 추가한다. V15 Java migration은 MongoDB 컬렉션과 조회 인덱스를 멱등하게 준비한다. MySQL과 MongoDB DDL이 하나의 트랜잭션으로 묶인다는 뜻은 아니다. Hibernate의 연결 처리는 트랜잭션 종료 후 반환으로 명시하며, OSIV가 있어도 응답 준비 중 SQL 연결이 남지 않는지 검사한다.

기존 데이터는 상태 필드가 없으면 확정 메시지로 읽고, 버전이 없으면 0으로 읽는다. 새 버전의 읽기·작업권 규칙을 모든 실행 인스턴스에 적용한 뒤 제한된 사용자 범위에서 쓰기를 전환해야 한다. 진행 중 작업을 정리하기 전에 PENDING을 모르는 구버전으로 되돌리지 않는다. 스키마·작업 기록을 삭제하는 rollback은 수행하지 않는다.

운영 재개 전에는 대상 프로젝트·리전·서비스명, 단계적 배포와 rollback 명령, 복구 주기 호출, MANUAL의 점검·재개 경로를 실제 환경에서 확정한다. 현재 내부 HTTP 복구·수동 재개 endpoint는 없다. Cloud Run 스케일 0에서 이 프로세스 내부 스케줄러만으로 정해진 시간 안에 복구된다고 가정하지 않는다.
