## Abstract

지원형 대화는 사용자가 현재 감정과 상황을 표현하고, 짧은 공감과 실행 가능한 행동 기술을 안내받는 단계형 경험이다. 완성되지 않은 온보딩을 자연스럽게 이어서 받고, 진행 중인 세션을 재개하며, 최근 대화를 다시 보여 주되 의료 진단이나 처방으로 넘어가지 않는 정서 지원 범위를 유지한다.

## Introduction

사용자가 대화를 시작하면 서버는 진행 중인 세션이 있는지 확인한다. 있으면 이전 단계와 메시지를 복원하고, 없으면 프로필 완성 상태에 맞는 첫 단계에서 새 세션을 연다. 프로필 정보가 충분한 사용자는 곧바로 감정과 상황을 돌아보는 흐름으로 들어간다.

대화는 자유 입력만 이어지는 구조가 아니다. 각 단계가 받을 수 있는 입력, 다음 단계, 사용자 상태 갱신, 봇 메시지 생성을 책임진다. 이 구조는 온보딩 질문, 감정 선택, 상황 설명, 행동 기술 제안과 피드백을 한 세션 안에서 예측 가능한 순서로 연결한다.

## Description

대화 상태는 크게 프로필 보완, 감정·상황 이해, 행동 제안, 실행 확인, 종료로 이동한다. 사용자는 중간에 나갔다가 같은 세션으로 돌아오거나, 원할 때 기존 미완료 세션을 닫고 새 대화를 시작할 수 있다.

stateDiagram-v2
    state "프로필 보완" as Onboarding
    state "감정 선택" as Emotion
    state "상황 표현" as Situation

    state "실행 피드백" as Feedback

    [*] --> Onboarding
    Onboarding --> Emotion: 필요한 맥락 충족
    Emotion --> Situation
    Situation --> Proposal
    Proposal --> Selection
    Selection --> Feedback
    Feedback --> Complete

~~~

세션의 단계와 사용자 연결은 일관된 관계 상태로 보존되고, 메시지는 시간순 대화 기록으로 보존된다. 이 분리는 대화 진행 상태를 안정적으로 판단하면서도 여러 형태의 봇 메시지와 사용자 입력을 자연스럽게 축적하게 한다. 최근 하루의 완료된 세션과 현재 진행 중인 세션은 하나의 시간순 이력으로 조회된다.

생성형 응답은 사용자의 감정, 상황, 프로필과 미리 정의된 행동 기술을 조합한다. 공감은 짧고 비판적이지 않아야 하며, 행동 제안은 작은 실행 단위로 제시된다. 응답은 사용자 입력을 지시로 승격하지 않고, 진단·평가·처방·복용 변경을 말하지 않는 안전 범위 안에서 생성된다.

일부 생성 결과에는 형식 검사와 기본 문구가 마련되어 있다. 사용자 응답은 요청 계정과 세션 소유자를 대조한다. 대화를 시작하거나 응답할 때 구독을 확인하는 절차는 비활성화되어 있어, 세션 소유권 검사만으로 유료 권한까지 보장하지는 않는다.

대화 메시지와 다음 단계는 문서 트랜잭션으로 함께 확정한다. 프로필도 변경하는 요청은 임시 대화와 관계 저장소의 커밋 근거를 사용해 공개·보상·복구를 결정한다. 임시 메시지는 대화 이력과 리포트에서 제외한다. 새 세션 생성과 삭제도 사용자별 작업권을 사용하며, 알림 예약·취소는 대화 확정 뒤에 수행한다.

현재 생성 요청 로그에는 사용자 상황·감정·프로필이, 일부 생성 결과 로그에는 응답 원문이 남는다. 생성 지침의 정서·의료 안전 범위와 운영 로그의 개인정보 보호는 별도로 검증해야 한다. 대화 처리에는 관계형 상태 저장, 메시지 저장, 외부 생성이 함께 관여하므로 부분 실패와 전체 저장의 원자성을 동일시하지 않는다.

## Conclusion

채팅의 개인 설계·검토 기록은 `.local/chat/`, 비교 코드와 장애 관측값은 그 아래 `experiments/`에서 관리한다. 공유 기능 설명은 로컬 자료 없이 이해할 수 있어야 한다.

지원형 대화의 핵심은 생성형 문장 자체보다 사용자가 어디까지 왔는지 기억하고, 필요한 맥락을 안전하게 수집하며, 공감에서 작은 행동으로 이어지는 순서를 지키는 데 있다. 세션과 메시지의 분리, 명시적인 단계 전이, 정서·의료 안전 경계가 이 경험을 반복 가능하게 만든다.
