## Abstract

구독 권한은 앱이 보낸 거래 식별자로 결제 제공자의 상태를 조회하고, 서명된 거래·갱신 정보와 서버 알림을 검증해 구독 상태로 저장한다. 사용자와 원래 거래 식별자의 고유 제약으로 중복 저장을 제어한다. 알림 도착 순서가 바뀌었을 때 최신 상태를 보존하는 검사는 현재 별도로 구현되어 있지 않다.

## Introduction

결제 권한은 금전과 서비스 접근을 함께 다루기 때문에 클라이언트가 보낸 상태, 만료일, 상품 정보만으로 결정할 수 없다. 서버는 서명된 거래 증거를 검증하거나 결제 제공자에게 최신 상태를 조회한 뒤에만 활성 여부와 만료 시각을 저장한다.

최초 검증 이후에는 갱신, 만료, 환불, 자동 갱신 변경 같은 서버 알림이 구독 상태를 계속 갱신한다. 앱은 서버에 저장된 상태를 조회해 현재 권한을 표시하며, 외부 검증이 실패한 경우 서버는 권한을 낙관적으로 새로 부여하지 않는다.

## Description

구독 상태는 결제 제공자의 상태를 활성·만료·취소로 정규화한다. 결제 재시도와 유예 상태도 활성으로 저장할 수 있지만, 실제 활성 판정에는 저장된 만료 시각이 현재보다 뒤라는 조건도 필요하다. 자동 갱신 해제는 곧바로 남은 이용 기간을 취소하는 동작과 다르다.

~~~mermaid
stateDiagram-v2
    state "활성" as Active
    state "만료" as Expired
    state "취소·환불" as Cancelled

    [*] --> Active: 검증된 신규 구독
    Active --> Active: 갱신·유예·재시도
    Active --> Expired: 만료
    Active --> Cancelled: 환불·강제 취소
    Expired --> Active: 검증된 재구독
    Cancelled --> Active: 검증된 새 거래
~~~

한 계정에는 하나의 구독 레코드만 존재하며, 결제 제공자가 부여한 원래 거래 식별자는 구독 계보를 찾는 기준이 된다. 같은 거래가 다시 도착하면 기존 상태를 갱신하고, 계보 식별자가 바뀌어도 먼저 사용자 계정의 기존 구독을 찾아 하나의 권한 상태로 수렴시킨다.

서버 알림은 바깥 알림과 내부 거래·갱신 증거를 각각 검증한 뒤 처리한다. 갱신과 신규 구독은 최신 만료와 자동 갱신 상태를 반영하고, 만료와 환불은 권한을 내린다. 알 수 없는 구독 계보나 지원하지 않는 알림은 기존 사용자 권한을 임의로 만들지 않고 안전하게 종료한다.

정식 결제 조회에서 거래를 찾지 못하면 시험 결제 환경으로 한 번 전환해 조회한다. 이는 모든 외부 오류를 일반적으로 재시도하는 정책은 아니다. 중복 저장 경쟁은 기존 구독을 다시 읽어 수렴시킨다. 서버 알림은 일부 업무 예외를 정상 종료하고 예상하지 못한 오류는 실패로 처리한다.

현재 로그에는 전체 거래 식별자가 남으며, 알림 처리에는 이벤트 중복 식별이나 발생 시각에 따른 역순 차단이 없다. 동일 레코드 갱신과 최신 상태 보존은 구분해야 한다. 또한 구독 상태 저장과 기능별 권한 강제는 별개로, 현재 대화의 구독 검사는 비활성화되어 있다.

## Conclusion

구독의 기준은 검증된 결제 증거와 서버 저장 상태다. 사용자당 하나의 레코드와 만료 시각 검사는 구현되어 있으며, 알림 순서 보존·민감정보 로그 정리·기능별 권한 강제는 별도의 보완 범위다.
